# FATLLM: دسترسی کامل Claude به سرور

یک دستور روی سرور می‌زنی، یک **کلید** می‌گیری.
کلید را به Claude می‌دهی و Claude با دسترسی root سرور را مدیریت می‌کند.

## خلاصه: سه قدم

**۱. روی سرور این را paste کن** (هر کاربری؛ اگر root نباشی خودش sudo می‌زند):

```bash
bash <(curl -Ls https://raw.githubusercontent.com/SaeedCrazy/FATLLM-FULL-ACCESS-TO-LLM-/HEAD/install.sh)
```

هیچ سؤالی نمی‌پرسد. آخرش یک خط چاپ می‌کند:

```
FATLLM key: https://1-2-3-4.sslip.io/fat_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

**۲. یک بار در تنظیمات محیط ابری Claude Code** (منوی محیط بالای جلسه → Edit):
- Network access را **Full** کن.
- (اختیاری) متغیر `FATLLM_KEY` را برابر کلید بگذار تا دیگر هیچ‌وقت کلید نفرستی.

**۳. یک جلسه روی همین ریپو باز کن** و آن خط را بفرست، بعد کارت را بگو.
- Claude خودش وصل می‌شود و برای دستورها تأیید نمی‌خواهد.
- اگر `FATLLM_KEY` را گذاشته باشی، از اول جلسه وصل است؛ فقط کارت را بگو.

### خودش چه کارهایی می‌کند
- پایتون و curl را اگر نباشد نصب می‌کند.
- گواهی HTTPS واقعی می‌گیرد؛ دامنه لازم نیست (`sslip.io`).
- پورتش **9001** است (اگر پر بود، یک پورت تصادفی آزاد بین 9002 تا 9999). به 80 و 443 دست نمی‌زند، پس با x-ui، nginx یا Caddy خودت تداخل ندارد. فایروال ufw/firewalld را هم خودش باز می‌کند.
- اگر گواهی واقعی نشد (مثلاً پورت 80 پر است یا سرور ایران است)، خودش HTTPS مستقیم با گواهی self-signed می‌زند.
- دوباره زدن همین دستور یعنی تعمیر یا آپدیت؛ کلید عوض نمی‌شود.

گزینه‌های اختیاری (بعد از دستور): `--domain my.site.com`، `--port 9001` یا `--port random`، `--tunnel`، `--expire 7d`.

### راه دیگر: چت معمولی claude.ai
Settings → Connectors → Add custom connector، آدرس = کلید + `/mcp`.
در تنظیمات همان کانکتور ابزارها را روی **Always allow** بگذار.

## پنل وب (روی گوشی)

لینک پنل = کلید + `/panel` (دستور `fatllm key` چاپش می‌کند). در مرورگر گوشی بازش کن:

- **خانه:** وضعیت سرور (پردازنده، حافظه، دیسک)، زمان روشن بودن، حالت دسترسی و کارهای سریع (پورت‌های باز، سرویس‌های خراب، به‌روزرسانی‌ها، داکر، ری‌استارت).
- **ترمینال:** دستور بنویس و اجرا کن، خروجی زنده، توقف، تاریخچه، اجرا «از طریق رله».
- **فایل‌ها:** مرور پوشه‌ها، دیدن و ویرایش فایل، آپلود و دانلود.
- **فعالیت:** همه‌ی کارهایی که Claude یا هر ایجنت دیگری کرده، با نتیجه (موفق/خطا) و دستورهای در حال اجرا.
- **تنظیمات:** کلید و آدرس MCP با دکمه‌ی کپی، راهنمای وصل کردن Claude Code / claude.ai / ChatGPT / بقیه، انقضای کلید، کلید تازه، خاموش کردن دسترسی، رله‌ها، تم تیره/روشن.

در حالت `direct` (گواهی self-signed) مرورگر یک بار هشدار می‌دهد: Advanced ← Proceed.

## منوی سرور و ظاهر ترمینال

نصب و همه‌ی دستورها خروجی رنگی و مرتب دارند (لوگو، تیک، اسپینر)، طوری که در ترمینال باریک گوشی هم به‌هم نریزد.

روی سرور فقط بزن `fatllm` تا منوی رنگی باز شود. عدد گزینه را بزن: نمایش کلید، لینک پنل، وضعیت، فعالیت‌ها، روشن/خاموش، کلید تازه، انقضا، رله‌ها، حالت دسترسی و آپدیت.

## دستورهای سرور

```
fatllm              منوی کامل (عدد گزینه را بزن)
fatllm key          نمایش کلید
fatllm rotate       کلید تازه؛ کلید قبلی فوراً باطل می‌شود
fatllm off / on     خاموش و روشن کردن دسترسی
fatllm status       وضعیت و تست
fatllm log          کارهایی که Claude کرده
fatllm expire 12h   کلید بعد از ۱۲ ساعت باطل شود (never = هیچ‌وقت)
fatllm port 9001    عوض کردن پورت (یا: fatllm port random)
fatllm relay ...    وصل کردن یک سرور دیگر (پایین را ببین)
fatllm update       آپدیت، کلید می‌ماند
fatllm uninstall    حذف کامل
```

## وصل کردن دو سرور (رله): هم سایت ایرانی، هم خارجی

«رله» یعنی یک سرور، ترافیکی که خودش به آن نمی‌رسد را از طریق سرور دیگر می‌فرستد.
- سایت‌های ایرانی (میکسین، درگاه‌ها) IP خارجی را بلاک می‌کنند → باید از IP ایران بروی.
- سایت‌های خارجی (تلگرام، AI) از داخل ایران فیلترند → باید از IP خارج بروی.

**روش پیشنهادی:** FATLLM روی **سرور خارج** (چون گواهی HTTPS و اتصال Claude راحت است)، و سرور ایران را به آن وصل کن. دو حالت دارد:

### رلهٔ معکوس (reverse) — وقتی سرور ایران از بیرون در دسترس نیست
سرور ایران معمولاً اتصال **ورودی از خارج** را نمی‌پذیرد (پنل و تونل هم به همین دلیل باز نمی‌شوند). پس خودِ سرور ایران به بیرون (سرور خارج) وصل می‌شود. روی **سرور خارج** بزن:

```
fatllm relay reverse add --name iran
```

یک بلوک آماده چاپ می‌کند. کل آن بلوک را **روی سرور ایران** (به‌عنوان root) paste کن. تمام. کلیدی که می‌سازد فقط اجازهٔ تونل دارد، نه ورود به شل. هیچ پسوردی هم رد و بدل نمی‌شود.

### رلهٔ معمولی (forward) — وقتی سرور مقصد از بیرون در دسترس است
اگر سرور دوم ورودی می‌پذیرد، روی سرور خارج بزن:

```
fatllm relay add --host <آی‌پی سرور دوم> --user root --name iran
```

پسوردِ روتِ آن سرور را یک‌بار (پنهان) می‌پرسد؛ ذخیره‌اش **نمی‌کند**، فقط با آن یک کلید SSH نصب می‌کند.

### بعد از هر دو
- سایت ایرانی: به Claude بگو «با رله‌ی iran چک کن» → `srv --via iran 'curl -s https://mixin.ir'` (از IP ایران بیرون می‌رود).
- بقیه: عادی، مستقیم از سرور خارج.

دستورهای رله:
```
fatllm relay list           رله‌ها و اینکه هرکدام بالاست یا نه
fatllm relay test iran      آی‌پی این سرور در برابر آی‌پی‌ای که از رله بیرون می‌رود
fatllm relay remove iran    حذف رله
```

(نکته: گرفتن گواهی Let's Encrypt از داخل ایران گاهی مشکل دارد؛ برای همین گذاشتن FATLLM روی سرور خارج و استفاده از رلهٔ معکوس ساده‌ترین راه است.)

## امنیت
- کلید یعنی **root کامل**. به کسی نده، جایی نگذار.
- اگر لو رفت: `fatllm rotate`. اگر کار نداری: `fatllm off`.
- همه‌چیز روی HTTPS است. کلید ۲۵۶ بیتی است و درخواست بدون کلید فقط 404 می‌گیرد.
- همه‌ی دستورهای Claude در `/var/log/fatllm/audit.log` ثبت می‌شود (`fatllm log`).

## اگر کار نکرد
- `fatllm status` را بزن و خروجی‌اش را به Claude بده.
- پورتی که آخر نصب گفته را در فایروال پنل سرور (Hetzner، Arvan، …) باز کن.
- در حالت تونل، آدرس بعد از ری‌استارت سرور عوض می‌شود؛ `fatllm key` را دوباره بزن.

## «This site can't be reached» روی سرور ایران

معمولاً یکی از این دوتاست: دامنه‌ی `sslip.io` در ایران فیلتر است، یا پورت در فایروال دیتاسنتر بسته است. روی سرور بزن:

```
fatllm mode direct
```

کلید و پنل از این به بعد خودِ IP سرور را دارند (بدون sslip.io)، روی پورت 9001. برای عوض کردن پورت: `fatllm port 9123` یا `fatllm port random`. بعد `fatllm key` را بزن و لینک تازه‌ی پنل را باز کن (هشدار مرورگر: Advanced ← Proceed). اگر باز هم باز نشد، پورتی که `fatllm key` نشان می‌دهد را در فایروال پنل دیتاسنتر باز کن.

## خطای Cloudflare 1033 یا آدرسی که مدام عوض می‌شود
این یعنی حالت **تونل** روی سرورت فعال شده (معمولاً چون پورت ۸۰ و ۴۴۳ پر بوده). تونل بی‌ثبات است و آدرسش با هر ری‌استارت عوض می‌شود. یک‌بار این را بزن تا یک آدرس ثابت بگیری:

```
fatllm mode direct
```

- خودِ سرویس روی یک پورت ثابت HTTPS می‌دهد (گواهی self-signed). آدرس دیگر عوض نمی‌شود و به Cloudflare وابسته نیست — از داخل ایران هم کار می‌کند.
- **Claude Code** خودش به این گواهی اعتماد می‌کند (`srv` موقع `srv key` آن را pin می‌کند). کاری لازم نیست.
- فقط **کانکتور وب‌سایت claude.ai** گواهی عمومی می‌خواهد؛ برای آن از `fatllm mode caddy` (اگر پورت ۸۰ آزاد است) یا `--domain` با یک دامنه‌ی واقعی استفاده کن.

سه حالت:
- `fatllm mode caddy` — گواهی واقعی روی یک پورت (به پورت ۸۰ یا ۴۴۳ آزاد نیاز دارد)
- `fatllm mode direct` — گواهی self-signed، آدرس ثابت، بدون نیاز به پورت ۸۰/۴۴۳ (پیشنهادی برای Claude Code)
- `fatllm mode tunnel` — تونل Cloudflare (آدرس با ری‌استارت عوض می‌شود)

### English (short)
`install.sh` installs a small Python agent (stdlib only) on 127.0.0.1 with HTTPS in front
(its own Caddy + Let's Encrypt on `<ip>.sslip.io`, or a Cloudflare quick tunnel), and prints a
key `https://host/fat_<token>`. `GET <key>` returns a usage guide for the AI; `POST <key>/run`
runs bash as root; `<key>/mcp` is an MCP server (Streamable HTTP) for claude.ai custom
connectors. Manage it with `fatllm` on the server. Tests: `python3 -m unittest discover -s test -v`.
