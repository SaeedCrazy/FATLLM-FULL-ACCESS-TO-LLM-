# FATLLM: دسترسی کامل ایجنت به سرورهایت

یک دستور روی سرور می‌زنی، یک **کلید** می‌گیری.
کلید را به Claude (یا GPT، Grok و هر ایجنت دیگر) می‌دهی و او با دسترسی root روی آن سرور، و روی هر سرور دیگری که وصل کنی، کار می‌کند. تأییدهای پشت‌سرهم ندارد و اگر اینترنت لحظه‌ای قطع شود، کار خراب نمی‌شود.

## سه قدم

**۱. روی سرور اصلی این را paste کن.** سرور اصلی همانی است که از بیرون در دسترس است، معمولاً سرور خارج. اسمش «هاب» است.

```bash
bash <(curl -Ls https://raw.githubusercontent.com/SaeedCrazy/FATLLM-FULL-ACCESS-TO-LLM-/HEAD/install.sh)
```

هیچ سؤالی نمی‌پرسد. آخرش یک خط چاپ می‌کند:

```
FATLLM key: https://1.2.3.4:9001/fat_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

**۲. یک بار در تنظیمات محیط ابری Claude Code** (منوی محیط بالای جلسه، بعد Edit):
- Network access را **Full** کن.
- (اختیاری) متغیر `FATLLM_KEY` را برابر کلید بگذار تا دیگر لازم نباشد کلید بفرستی.

**۳. روی همین ریپو یک جلسه باز کن**، آن خط را بفرست و کارت را بگو.

## وصل کردن سرورهای دیگر (مثلاً سرور ایران)

روی هاب بزن:

```
fatllm add-server iran
```

یک خط چاپ می‌کند. آن را روی سرور ایران (با کاربر root) paste کن. تمام!

- سرور ایران **خودش** به هاب وصل می‌شود؛ پورت باز و IP قابل‌دسترس لازم ندارد. پس حتی وقتی سرور ایران از بیرون بسته است کار می‌کند.
- آن خط یک‌بارمصرف است و ۲ ساعت اعتبار دارد.
- از پنل هم می‌شود: «افزودن سرور». پنل منتظر می‌ماند تا وصل شود و خبر می‌دهد.
- ایجنت با همان کلید روی همه‌ی سرورها کار می‌کند: `srv --on iran '...'`. مثلاً سایت‌های ایرانی را از سرور ایران چک می‌کند و تلگرام و گیت‌هاب را از سرور خارج.
- اگر اتصال قطع شود، سرور خودش دوباره وصل می‌شود. دستوری که در حال اجراست ادامه پیدا می‌کند.
- آپدیت هم یک‌جاست: `fatllm update` روی هاب، همه‌ی سرورها را آپدیت می‌کند.

## پنل وب (روی گوشی)

لینک پنل همان کلید است با `/panel` در آخرش. `fatllm key` چاپش می‌کند. ظاهرش همان تم Pingo پنل‌های EZ است: تیره/روشن، شیشه‌ای و مخصوص گوشی.

- **خانه:** همه‌ی سرورها با وضعیت آنلاین/آفلاین، عقربه‌های پردازنده، حافظه و دیسک، و کارهای سریع.
- **انتخاب سرور:** از دکمه‌ی بالای صفحه. ترمینال و فایل‌ها روی همان سرور کار می‌کنند.
- **ترمینال:** دستور اجرا کن و خروجی را زنده ببین. اگر اتصال قطع شود، دستور دوباره اجرا نمی‌شود؛ فقط نتیجه‌اش گرفته می‌شود.
- **فایل‌ها:** مرور، دیدن، ویرایش، آپلود و دانلود.
- **فعالیت:** هر کاری که ایجنت روی هر سرور کرده، با نتیجه‌اش.
- **تنظیمات:** کلید و پیام آماده برای ایجنت، انقضا، **کلیدهای جدا برای هر ایجنت**، کلید تازه و خاموش کردن.

گواهی پیش‌فرض خودامضاست. پس مرورگر یک بار هشدار می‌دهد: Advanced ← Proceed. این طبیعی است.

## منوی سرور

روی سرور فقط بزن `fatllm`. یک منوی رنگی باز می‌شود و عدد گزینه را می‌زنی. دستورهای مستقیم:

```
fatllm key               کلید و لینک پنل
fatllm status            همه‌چیز سالم است؟ کدام سرورها آنلاین‌اند؟
fatllm add-server NAME   وصل کردن یک سرور دیگر
fatllm servers           فهرست سرورها
fatllm remove-server N   حذف یک سرور (با --uninstall از روی خودش هم پاک می‌شود)
fatllm log               کارهایی که ایجنت کرده
fatllm keys              کلیدهای جدا (keys add gpt 7d / keys remove gpt)
fatllm rotate            کلید تازه؛ کلید قبلی همان لحظه باطل می‌شود
fatllm expire 7d         انقضا (30m، 12h، 7d، never)
fatllm off / on          خاموش/روشن کردن دسترسی
fatllm port 9123         عوض کردن پورت (یا random)
fatllm mode cert         گواهی عمومی برای کانکتور claude.ai (پورت 80 باید آزاد باشد)
fatllm update            آپدیت هاب و همه‌ی سرورها
fatllm uninstall         پاک کردن کامل
```

روی سرورهای وصل‌شده: `fatllm status`، `fatllm log`، `fatllm off/on` و `fatllm leave` (جدا شدن و پاک شدن).

## چند نکته

- **پورت:** پیش‌فرض 9001 است. اگر پر باشد، یک پورت آزاد تصادفی بین 9002 و 9999. به 80 و 443 دست نمی‌زند، پس با x-ui، nginx یا Caddy تداخل ندارد. ufw و firewalld را خودش باز می‌کند. فایروال پنل دیتاسنتر (Hetzner، Arvan و …) را خودت باز کن.
- **آدرس:** آدرس خودِ IP است، بدون sslip.io و Cloudflare، پس از ایران هم باز می‌شود. با ری‌استارت عوض نمی‌شود.
- **دوباره زدن دستور نصب** یعنی تعمیر یا آپدیت. کلیدها، پورت و سرورهای وصل‌شده می‌مانند.
- **کانکتور claude.ai یا ChatGPT** گواهی عمومی می‌خواهد: `fatllm mode cert`. آدرس MCP همان کلید است با `/mcp`. Claude Code به این لازم ندارد.

## امنیت

- کلید یعنی **root کامل روی همه‌ی سرورهای وصل‌شده**. جایی منتشرش نکن.
- برای هر ایجنت یک کلید جدا بساز تا هر وقت خواستی فقط همان را قطع کنی (`fatllm keys`).
- اگر لو رفت: `fatllm rotate`. اگر فعلاً کار نداری: `fatllm off`.
- همه‌چیز روی HTTPS است. گواهی خودامضا pin می‌شود، پس کسی وسط راه نمی‌تواند خودش را جای سرور جا بزند.
- کلید ۲۵۶ بیتی است و درخواست با کلید غلط فقط 404 می‌گیرد. کلید هیچ‌وقت در لاگ نوشته نمی‌شود.
- سرورهای وصل‌شده هیچ پورتی باز نمی‌کنند. هر کدام کلید مخصوص خودش را دارد که فقط برای همان اتصال است.
- همه‌ی کارهای ایجنت ثبت می‌شود (`fatllm log` یا بخش فعالیت پنل).

## اگر کار نکرد

- `fatllm status` را روی هاب بزن و خروجی‌اش را به Claude بده.
- پورتی که `fatllm key` نشان می‌دهد را در فایروال پنل دیتاسنتر باز کن.
- سرور وصل‌شده آفلاین است؟ روی خودش `fatllm status` بزن؛ دلیلش را می‌گوید (مثلاً به هاب نمی‌رسد).
- از نسخه‌ی ۱ آمده‌ای؟ همان دستور نصب را دوباره بزن. کلیدت می‌ماند. رله‌ها و تونل قدیمی حذف می‌شوند؛ به‌جای رله، سرور دیگر را با `fatllm add-server` وصل کن.

### English (short)
A hub runs `server/agent.py` (Python 3.6+, stdlib only), serving HTTPS on port 9001 with a
long-lived self-signed certificate (pinned by clients) or, optionally, a Let's Encrypt one via
Caddy. Other servers join with a one-time line from `fatllm add-server NAME`; they dial out to the
hub and long-poll for work, so they need no open port (works for servers behind NAT or inbound
filtering). The key `https://ip:9001/fat_<token>` gives: `GET <key>/` a guide for the AI,
`POST <key>/run?on=NAME` bash as root with idempotent job ids, `<key>/file`, `<key>/mcp` (MCP over
Streamable HTTP), `<key>/panel` (web panel). Manage with `fatllm` on the hub.
Tests: `python3 -m unittest discover -s test -v`.
